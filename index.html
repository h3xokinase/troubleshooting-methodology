Applying the CompTIA Troubleshooting Methodology

Author: John Riel Cruz (COMP001022336869) • Date: October 22, 2026
Category: IT Support & Technical Troubleshooting

Introduction

Learning and being able to apply the 6-Step Troubleshooting Methodology has changed how I approach technical problems. It is easy to follow and understand. It saves time, rather than applying a fix right away when you aren't sure if it's right. For me to memorize, I used the first letters of the the first words of the steps (IETEVD - I for Identify the problem and so on).

Below is an in-depth breakdown of how to apply this methodology to real-world technical scenarios.

Step 1: Identify the Problem

Gather information from users. Ask if there are error messages or beep sounds. Ask if there were changes. Ask what was he/she doing before the error occured. You can also ask if another technician already checked the device. If that's so, it might can be helpful if you talk with the technician as well. Non-technical users can't clearly explain what happened so we must be patient and listen carefully. We can recommend the right words next time they ask for help so that it will be clearer and easier to learn what really is the issue. Another important thing to initially do is backup data before making changes.

Step 2: Establish a Theory of Probable Cause

A physical inspection is helpful. An example based on experience is there are insect infestation and liquid damage. You can listen for beeps and check for lights. You can smell for possible burn damage. Unusual sounds like noisy fans and ticking inside the device. Make sure that all cables are plugged in all the way. You can check also from the documentation/website/forums of the vendor/brand. You may take with other technicians as they might've already encountered the same problem before. Eliminate what is working so that you can isolate and narrow it down. Since we have a ticketing system that has knowledge base, we can easily browse for a problem with solution and also, add another topic for future use.

Step 3: Test the Theory of Probable Cause

One good way to test your theory is to test it on a test machine. Try to replicate the problem to another device so that if it fails, it won't really be that critical. Also, unplug the power before operating on the device. If your test works, you have found the root cause but remember, there can be one or more possible fixes. If the theory fails, go back to establishing a new theory. If you run out of theories, it's time to escalate to your senior technician or contact the vendor and ask for warranty. You may also use social media to ask other professionals and see if they might be helpful. Be careful though and remember not to share confidential information.

Step 4: Establish a Plan of Action and Implement the Solution

Create your step-by-step plan. If you plan to replace the damaged part, consider the cost. Think if it's beyond economic repair. Buying the part and continue using the machine or better buy a new machine. This gives you warranty and longer lifespan. Others might consider workarounds. It will fix the problem and help you continue using the machine normally. But remember that this is only a temporary fix and might work only on a short period of time. The workaround should be documented so that other technicians are informed. Create a backup plan like backing up your data or create a restore point before making major changes so that you can revert anytime.

Step 5: Verify Full System Functionality and Implement Preventative Measures

Test the result of the fix. Also, involve the user. Let them do the testing so that both of you can confirm the test actually fix the problem. Make the user agree that it is working. One proof can be the use of ticketing. On our ticketing system, there is a survey the once you resolve/close the ticket, the user will receive a survey wherein they can select if they are satisfied with what the technician did. Take steps to ensure that the problem doesn't happen again. Educate the user the do's and dont's for example, don't edit the registry. Inform them that it's okay to run the updates (windows/mac updates) if there's available.

Step 6: Document Findings, Actions, and Outcomes

This is the final step, yet this is very important. Document everything, including the steps done on the knowledge base. This will be helpful for future use and consume less time. Also, you can input the machine/part's history so that other technicians will know if there are history of repairs. Also, tag machines/ports that are faulty so other technicians will not try to fix those.

Conclusion

Learning the CompTIA's troubleshooting methodology helped me enjoy working on issues/problems on a daily basis. By strictly following each step, you won't miss a thing and you will be able to solve the issue successfully. Some of the important things that I always remember and do is always have a back up and using the knowledge base for proper documentation.
